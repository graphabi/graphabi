# GraphABI v0.1.0-alpha.2 release notes

Status: prepared for maintainer approval. The tag and GitHub release do not exist, and no package
has been published to PyPI or TestPyPI.

## Added

- Complete graph contract coverage in report JSON, CLI output, and self-contained HTML, including
  contracted and observed intersections plus an explicit statement that coverage is not
  correctness.
- Trace schema 0.2 causal occurrence identities and deterministic pairing for loops, retries,
  repeated edges, fan-out, fan-in, nested branches, and multiple terminal paths.
- A narrow local OTLP/JSON importer for the documented OpenInference and OpenTelemetry GenAI
  mapping profile. Unsupported and ambiguous spans remain `UNKNOWN`.
- An optional OpenAI Agents SDK `>=0.20,<0.21` adapter with local keyless integration coverage.
- Deterministic prompt and retriever migration examples plus an optional, manually authorized live
  model migration example with a keyless fixture fallback.
- Conservative `graphabi init` onboarding and evidence-counted, unenforced contract inference.
- A reusable GitHub Action with stable exit policy, a bounded job summary, and an offline report
  artifact.
- A reproducible ten-case semantic regression corpus. It is project test data, not an industry
  benchmark.

## Compatibility and migrations

| Surface | Alpha.2 behavior | Compatibility path |
|---|---|---|
| Contract | Schema 0.2 adds explicit `graph_edges` topology. | Schema 0.1 contracts still load with incomplete-inventory limits. |
| Trace | Schema 0.2 adds causal node and edge occurrence identity. | Trace 0.1 remains readable; SQLite migration preserves single-occurrence records. |
| Report | Schema 0.3 adds complete coverage and occurrence pairing. | Report 0.1 and 0.2 JSON remain accepted and are migrated on load. |
| Storage | Edge rows are keyed by occurrence. | Existing trace 0.1 databases migrate through the storage layer. |
| CLI | `init`, `import-otel`, expanded `infer`, coverage output, and stable exit `3` uncertainty. | Existing commands and exit `0`, `1`, and `2` meanings remain. |

No schema compatibility is described as semantic equivalence. `UNKNOWN` and
`INSUFFICIENT_EVIDENCE` remain non-passing outcomes.

## Maintained adapters

- LangGraph `>=1.0,<1.3`
- OpenAI Agents SDK `>=0.20,<0.21`

The local telemetry importer is an interoperability adapter with an exact documented mapping, not
a claim of universal OpenTelemetry or OpenInference support.

## Verification snapshot

- Python: 3.12 and 3.13 required in CI
- Tests: 194
- Coverage: 91.37% with a 90% enforced floor
- Evaluator families: seven
- Regression corpus: ten deterministic cases
- Package artifacts: source distribution and universal Python wheel
- Default demo: deterministic, local, keyless, and intentionally breaking

The local benchmark still measures one synthetic linear graph at 10, 100, and 1,000 nodes. It is a
regression signal only and does not establish production scale or capacity.

## Public surfaces

- Core repository README and documentation describe only merged behavior.
- The project website shows report schema 0.3, current proof counts, maintained trace inputs,
  migration evidence, the corpus, and the GitHub Action without adding a new visual system.
- The organization profile retains the deterministic keyless command and direct repository,
  website, contribution, and security paths.

## Known limitations

- A pass covers only explicit contracts and selected observations, not unseen inputs or universal
  behavior.
- Ambiguous repeated occurrences remain `INSUFFICIENT_EVIDENCE`.
- Original Pydantic constraints are not reconstructed from stored payload values.
- The local SQLite store is single-process and is not a hosted telemetry backend.
- Report masking is best effort and is not a general data-loss-prevention system.
- OpenAI Agents Realtime, voice, streamed runs, sessions, and implicit handoff payload semantics are
  not mapped.
- The optional live model example can incur cost only after explicit acknowledgement, and either
  model may pass or fail.
- The GitHub Action targets GitHub.com; its artifact dependency does not support GitHub Enterprise
  Server.

## Publication boundary

After every required check passes from a clean clone, the maintainer should report the exact main
commit, artifact SHA-256 checksums, and remaining limitations. Creating `v0.1.0-alpha.2`, publishing
the GitHub release, and publishing to any package index require explicit approval.
