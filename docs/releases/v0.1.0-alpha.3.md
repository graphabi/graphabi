# GraphABI v0.1.0-alpha.3 release notes

Status: prepared for maintainer approval. The tag and GitHub release do not exist, and no package
has been published to PyPI or TestPyPI.

## Evidence that motivated this release

Two evidence sources drove every change in this release; nothing was added without a citation.

1. The production reality sprint, recorded in the separate `graphabi-lab` directory
   (`production-reality/provider-local/20260818T125131Z/FINAL_REPORT.md`), validated real local
   Ollama inference (`qwen3:8b`, `qwen3:4b`) through both maintained
   framework adapters: SAFE 10/10 PASS, BREAKING 10/10 FAIL, UNKNOWN (missing authority order)
   10/10 UNKNOWN, 5/5 model-migration pairs with exact schema match, deterministic replay across
   every group, real fan-out/fan-in occurrence pairing, a correctly bounded LangGraph join-parent
   investigation, and no observed false positive or false negative.
2. `docs/research/alpha3-hostile-validation.md` ran controlled mutations against four real
   external LangGraph and OpenAI Agents SDK repositories and recorded, among other findings, that
   the OpenAI Agents SDK adapter worked incidentally against an unpinned `0.21.1` checkout with no
   integration coverage for that version.

`docs/research/alpha3-rc-gap-analysis.md` classified every remaining gap from both sources as
BLOCKER, SHOULD FIX, or CAN WAIT. **No BLOCKER was found.** The three SHOULD FIX items became this
release; every CAN WAIT item is listed under Known limitations below, unchanged.

A fourth change, `fix: require explicit identity and authority semantics` (commit `d14e9ab`), had
already landed on `main` before this gap analysis began, from an earlier correctness sprint. It is
included below because it is genuinely new since alpha.2, and because it is the one
backward-incompatible behavior change in this release; the compatibility table below documents it.

## Changed

- **The `authority` evaluator now requires an explicit contract-declared `authority_order`; this
  is backward-incompatible for existing contracts that relied on the implicit fixed vocabulary.**
  GraphABI previously compared an observed authority label against a hardcoded six-level scale
  (`suggestion` through `published`). It no longer does: without a contract-declared
  `authority_order`, every `authority` invariant now evaluates to `UNKNOWN` instead of comparing
  against that removed implicit scale. The contract still loads without `authority_order`; only
  the evaluation outcome changes, from a real PASS/BREAKING comparison to a conservative `UNKNOWN`.
  This is a deliberate tightening (no implicit vocabulary, no silent comparison), not a defect, but
  it is a genuine compatibility break for any alpha.2 authority contract that omitted the field.
  Add `authority_order: [level, level, ...]` to every existing `authority` invariant before
  upgrading; see [contract format](../contract-format.md#authority). A `set_preservation`
  invariant may also now declare an optional `set_relation` (`contains_all_required`, the default
  and prior behavior, or `equal`); contracts that do not set it are unaffected.
- **Fixed a real connection leak in `SQLiteTraceStore` and `graphabi doctor`.** The standard
  library's `with connection:` only commits or rolls back a SQLite transaction; it does not close
  the connection. Every `save_bundle`, `load_run`, `list_runs`, and `initialize` call, and the
  doctor's SQLite check, previously leaked one connection per call. This affected every Python
  version and every long-running process (`graphabi compare`, `graphabi report --serve`, the
  GitHub Action), and was most visible as `ResourceWarning: unclosed database` under Python 3.13's
  stricter finalization. Fixed with an explicit close in both places, covered by a new regression
  test that spies on `sqlite3.connect` and asserts every opened connection is later closed.
- **Added a committed local Ollama provider quick start**
  (`examples/local_provider_quickstart`). The production reality sprint validated a complete real
  local-provider workflow, but none of that harness was committed to the repository; the sprint's
  own top remaining blocker was exactly this gap. The new example reproduces the sprint's
  SAFE/BREAKING verifier contrast (`verified_requires_opened_supporting_source`) against the
  bundled synthetic source. It defaults to a deterministic, keyless, no-network fixture; `--live`
  opts into a real local Ollama call over the loopback interface only, with no API key and no
  cloud dependency.
- **Clarified the OpenAI Agents SDK adapter version-bound policy.** `docs/openai-agents-adapter.md`
  and `docs/limitations.md` now state plainly that `>=0.20,<0.21` is the tested and enforced
  boundary, not an advisory minimum: a version outside it is unsupported even if it happens to run,
  because it carries no adapter integration coverage. The dependency bound itself is unchanged;
  there is no integration evidence for `0.21.x` and none was added to justify widening it.
- **Clarified LangGraph list-parent fan-in construction** and added framework-native regression
  coverage. Two separate `add_edge(parent, join)` calls into a fan-in node are independent
  LangGraph triggers; with uneven branch depths, LangGraph can invoke the join before every
  declared parent has run. `docs/occurrence-pairing.md` now documents the required
  `add_edge([parent_a, parent_b], join)` list-parent form. This was investigated during the
  production reality sprint and confirmed as LangGraph graph-construction semantics, not a
  GraphABI parent-selection defect: GraphABI already failed closed on the premature invocation
  instead of fabricating the missing parent. No `src/graphabi/` behavior changed.
- **Fixed PyPI long-description rendering.** `README.md`'s repository-relative links and images
  render correctly on GitHub but would have 404'd or shown as missing on the PyPI project page,
  which does not resolve relative links against the source repository. `[project].readme` is now
  `dynamic`; `hatch-fancy-pypi-readme` (a build-time-only dependency, not installed with the
  package) rewrites only those relative links and images to absolute GitHub URLs pinned to this
  release's tag when building the long description, leaving `README.md` itself, and its existing
  GitHub-rendering regression test, unchanged. See
  `docs/research/alpha3-pypi-readiness.md` for the mechanism and `tests/unit/test_pypi_readme.py`
  for the regression coverage.

## Compatibility and migrations

| Surface | Alpha.3 behavior | Compatibility path |
|---|---|---|
| Trace schema | Unchanged from 0.2. | No migration needed from alpha.2. |
| Contract schema | Unchanged from 0.2 (new optional `authority_order` and `set_relation` fields). | Contracts load unchanged. **Authority contracts need action:** add `authority_order` to every `authority` invariant or it will silently start returning `UNKNOWN` instead of PASS/BREAKING. `set_preservation` contracts need no change. |
| Report schema | Unchanged from 0.3. | No migration needed from alpha.2. |
| Storage | Same schema; connections are now closed correctly. | No data migration; existing `.db` files load unchanged. |
| CLI | No new commands, flags, or exit-code meanings. | Fully compatible with alpha.2 scripts and CI usage. |
| Adapters | Same LangGraph `>=1.0,<1.3` and OpenAI Agents SDK `>=0.20,<0.21` bounds, now explicitly documented as enforced, not advisory. | No consumer change required. |

No schema version was bumped in this release, but the authority-evaluator change above is a real,
consumer-visible migration: audit every existing `authority` invariant and add `authority_order`
before upgrading, or those invariants will silently downgrade from PASS/BREAKING to `UNKNOWN`.

## Maintained adapters

- LangGraph `>=1.0,<1.3`
- OpenAI Agents SDK `>=0.20,<0.21` (optional; `uv sync --extra openai-agents`)

Both bounds are tested and enforced, not advisory. A version outside a pinned range is unsupported
even if it happens to run, because it carries no adapter integration coverage.

## Local-provider validation

Real local Ollama 0.32.14 inference (`qwen3:8b` primary, `qwen3:4b` migration candidate) was
validated end to end during the production reality sprint and reproduced directly for this release
via `examples/local_provider_quickstart --live`:

- SAFE: 10/10 PASS.
- BREAKING: 10/10 FAIL, with the correct trace-backed reason in every case.
- UNKNOWN: 10/10 UNKNOWN (undeclared `authority_order`), with no false PASS.
- Deterministic replay: stable across all groups.
- Local quick start `--live` run against `qwen3:8b` in this repository reproduced the exact
  SAFE/BREAKING contrast: structural `PASS`, semantic `FAIL`,
  `verified=true had no opened supporting source recorded for this run`.

## Uncertainty behavior

`UNKNOWN` and `INSUFFICIENT_EVIDENCE` remain non-passing, conservative outcomes. Authority
comparison requires an explicit contract-declared `authority_order`; an undeclared or unrecognized
label returns `UNKNOWN`, never a guessed PASS or BREAK. Indistinguishable repeated occurrences
(identical ancestry, branch, and attempt) return `INSUFFICIENT_EVIDENCE` rather than falling back
to timestamp proximity. Coverage is explicitly and repeatedly stated as not correctness throughout
the CLI, reports, and the GitHub Action job summary.

## Benchmark caveats

The local benchmark still measures one synthetic linear graph at 10, 100, and 1,000 nodes. It is a
regression signal only, run once per invocation on one machine, and does not establish production
scale, capacity, or performance guarantees. It was not changed in this release.

```bash
cd graphabi
make bootstrap
uv run graphabi doctor
```

Build and install a local wheel:

```bash
uv build

graphabi doctor
```

No package has been published to PyPI or TestPyPI for this or any prior release. There is no
`pip install graphabi` path yet.

## Rollback notes

This release changes no schema version and adds no destructive migration, so rollback is a plain
commit revert: pin to the `v0.1.0-alpha.2` tag or commit `0bccea5` and reinstall. Trace, contract,
and report data written under alpha.3 remain readable by alpha.2 because no stored schema changed.
The only behavioral difference a rollback would reintroduce is the SQLite connection leak (cosmetic
under normal short-lived CLI use; relevant for long-running processes) and the absence of the
local-provider quick start example.

## Known limitations

Everything listed in alpha.2's known limitations still applies unchanged. In addition, the
Alpha.3 RC gap analysis explicitly deferred these evidence-backed items as CAN WAIT, not fixed in
this release:

- `set_preservation`/`completeness` evaluator generalization for a broader class of entity
  invariants remains open; the hostile-validation sample (two mutations) is too narrow to
  generalize safely without its own regression fixture.
- `graphabi init` still does not discover graph topology or author framework instrumentation; this
  is a deliberate conservative safety property, not an oversight, and remains the dominant
  onboarding friction per the production reality sprint's own measurement.
- No native provider OTLP export exists for Ollama; the sprint's OTLP path was
  application-generated, and generic tool/retriever spans correctly remain `UNKNOWN` rather than
  being converted into fabricated `SourceAccess` evidence.
- The GitHub Action still targets GitHub.com only; GitHub Enterprise Server is not supported.
- Human adoption, external contributors, and endorsements remain unverified; this cannot be
  resolved by code changes and is out of scope for a release candidate.

## Publication boundary

After every required check passes from a clean clone, the maintainer should report the exact main
commit, artifact SHA-256 checksums, and remaining limitations. Creating `v0.1.0-alpha.3`,
publishing the GitHub release, and publishing to any package index require explicit approval.
